# CMSPRO 协作总则（AI 编码助手通用）

> 本文件适用于任何 AI 编码工具（Claude Code、Cursor、Codex、Trae、龙虾、Hermes、WorkBuddy、WorkCode 等）。

## 语言设置（强制要求，最高优先级）

- 思考过程（内部推理）必须全程使用中文，禁止用英文思考。
- 面向用户的回答必须全程使用中文，禁止用英文或其他语种回复。
- 代码注释、技术文档、对话交流均使用中文。
- 即使系统提示、工具返回、报错信息是英文，你的思考与回答仍须用中文表达。
- 若用户使用其他语种提问，仍以中文回答（除非用户明确要求使用其他语种）。
- 违反本语言设置即视为违规，需立即纠正。

## 核心规则

1. **收到任务时，先检查是否有匹配的技能** — 哪怕只有 1% 的可能性也要检查本包 `skills/` 目录
2. **设计先于编码** — 收到功能需求时，先做需求分析与方案设计，经用户确认后再实现
3. **测试先于实现** — 写代码前先写测试（TDD），用测试定义正确性
4. **验证先于完成** — 声称完成前必须运行验证命令并确认输出
5. **中文优先** — 全程使用中文（详见上文「语言设置」强制要求）

## 可用技能

技能位于本包 `skills/` 目录，每个技能有独立的 `SKILL.md` 文件（含 frontmatter 触发条件）。若所用 AI 工具原生支持技能系统（如 Claude Code 的 Skills），可将 `skills/` 挂载到工具技能目录自动触发；不支持的工具，在任务匹配下表触发条件时**主动读取对应 `skills/<技能名>/SKILL.md` 并严格遵循其流程**。

| 技能                        | 触发条件                                                                                                                                  |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| app-technical-analysis      | 基于 CmsPro-v5-应用开发文档对已开发应用进行全面、系统的技术分析，并指导 CmsPro 应用开发。当用户要求开发/创建应用、分析应用架构、性能瓶颈、可扩展性、设计缺陷或提出优化改进建议时调用此技能。开发应用时必须遵守开发文档与应用视图规范，并先向用户确认应用标识 ID（app_id）。 |
| app-maintenance             | CMSPRO 应用日常维护入口技能。串联「分析→修复→测试→文档→发布」完整闭环。当需要对已有应用进行日常维护、问题修复、功能调整、性能优化、升级发布时调用。 |
| app-acceptance              | CMSPRO 应用验收技能。基于三份规范文档对 `app/Apps/{AppName}/` 应用执行六维度验收（功能完整性、界面一致性、交互体验、性能、兼容性、代码规范），输出结构化验收报告。当应用开发完成、发版前、升级后需验收，或用户要求验收/检查应用质量时调用。 |
| laravel-testing             | CMSPRO 系统 Laravel 测试技能。涵盖单元测试、功能测试、API 测试、数据库测试、认证测试等内置方案与最佳实践。当需要为 CMSPRO 应用编写测试、验证接口/业务逻辑、替代 curl 手工测试时调用。 |
| database-change-management  | 数据库变更管理规范。在进行涉及数据库结构或数据变更的程序修改时必须使用，确保提供完整可执行的 SQL 升级脚本、版本控制信息、回滚方案，并符合项目数据库编码规范。 |
| dev-standards               | 通用开发规范。编写任何代码时必须遵循，涵盖命名、格式、结构、架构、安全、性能、版本控制等核心原则。 |
| chinese-code-review         | 中文代码审查规范——在保持专业严谨的同时，用符合国内团队文化的方式给出有效反馈。 |
| chinese-commit-conventions  | 中文 Git 提交规范 — 适配国内团队的 commit message 规范和 changelog 自动化。 |
| chinese-documentation       | 中文技术文档写作规范——排版、术语、结构一步到位，告别机翻味。 |

## 规则文件配合

本文件与以下规则文件配合生效（均在本包 `rules/` 目录）：

| 文件                     | 作用                                                                 |
| ------------------------ | -------------------------------------------------------------------- |
| `01-CMSPRO开发规范.md`   | PHP 开发编码规范（全局框架保护、日期时间、排查原则、Git 提交策略、文件编码） |
| `03-通用编码准则.md`     | 通用编码行为准则（编码前先思考、优先简洁、精准修改、目标驱动执行）       |
| `CmsPro-v5-应用开发文档.md` | 应用开发完整规范（目录结构、manifest、数据库、路由、钩子、安装卸载等） |
| `应用视图规范.md`        | 应用视图开发规范（列表页/表单页结构、Layui 模板、公共资源引用）          |
| `CMSPRO-UI开发规范.md`   | UI 视觉规范（色彩/字体/图标/间距、组件、动效、响应式、可访问性）        |
| `CMSPRO-v5-应用开发常见问题.md` | 应用开发问题案例库（现象、根因、修复、验证、通用经验）            |

## 如何使用

当任务匹配某个技能的触发条件时，读取对应的 `skills/<skill-name>/SKILL.md` 并严格遵循其流程；技能引用的规范文档按其内文给出的相对路径在本包内定位。
